# Tables for the web

The offline, installable web version of Tables: the same Swift engine the Apple apps use (`../Engine`), compiled to WebAssembly, behind a web interface built on the Tables design system. No Node packages: the build is Swift and a shell script, and the page is plain HTML, CSS and JavaScript modules.

- [PLAN.md](PLAN.md): the porting plan and where it stands.
- [design/](design/): the design system. Rules are in `design/DESIGN.md`.

## Layout

| Folder | What's in it |
| --- | --- |
| `index.html`, `manifest.webmanifest`, `sw.js` | The page, the install manifest and the offline service worker |
| `app/` | The window: grid, menus, inspector, files, autosave, strings |
| `engine/` | The engine's WebAssembly interface (Swift), its WASI host, worker and loader (JavaScript), and smoke tests |
| `strings/` | The web app's own string catalogue (`.xcstrings`, five languages) |
| `design/` | Design tokens, components, menus, lint and specimen |
| `build/`, `dist/` | Generated by `build.sh`, not checked in: the build, and the site to publish |
| `deploy/`, `wrangler.jsonc` | Publishing to Cloudflare: headers, `robots.txt`, sitemap |
| `social/` | The picture shown when a link is shared, and the script that draws it (`swift social/make-og-image.swift`) |

## Setting up

The engine builds with the open-source Swift toolchain and its Swift SDK for WebAssembly, of exactly the same version. Xcode's own toolchain can't use the SDK.

1. Install the swift.org toolchain, for example Swift 6.4.2 from [swift.org/install](https://www.swift.org/install/). On a Mac it installs to `~/Library/Developer/Toolchains`.
2. Install the matching Swift SDK for WebAssembly:

   ```sh
   swift sdk install https://download.swift.org/swift-6.4.2-release/wasm-sdk/swift-6.4.2-RELEASE/swift-6.4.2-RELEASE_wasm.artifactbundle.tar.gz \
       --checksum 83baca83553f8c443cda7b84800912e6e709c3acd2e7ebf277794ca5836c0da5
   ```

`build.sh` looks for these at their default locations; set `SWIFT_TOOLCHAIN` and `SWIFT_SDK` to use others.

## Building and running

```sh
./build.sh                # engine, strings and offline file list, into build/
./build.sh --skip-engine  # after changing only the page's own files
npm run serve             # http://localhost:8000 (the specimen is at /design/)
npm test                  # engine smoke tests; pass .xlsx/.numbers/.csv paths to open them too
npm run lint:design       # design rules
```

On `localhost` the offline service worker only installs when the address has `?offline`, so that edits show up without a rebuild. Anywhere else it always installs.

## Deploying

The app is published at [tables.atelier.ktgk.app](https://tables.atelier.ktgk.app) as a Cloudflare Worker that serves only static files (`wrangler.jsonc`).

- `build.sh` assembles the site into `dist/`: just the files the page uses, plus `deploy/_headers`. The engine goes up gzipped (`build/tables-engine.bin`, about 20 MB; not named `.gz`, which Cloudflare answers with a bot challenge) because Cloudflare serves files of at most 25 MiB; the worker decompresses it. `build.sh` stops if any file is too large.
- Every push to `main` that touches `Web/` or `Engine/` builds, tests and deploys through `.github/workflows/web.yml`. Pull requests are built and tested only. The workflow runs `deploy/ci-build.sh`, which installs Swift and its SDK for WebAssembly, builds the site and runs the engine smoke tests. Swift is kept in the Actions cache, so it's only downloaded again when that script changes. The workflow needs the repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
- To deploy by hand from a Mac: `./build.sh && npx wrangler deploy`. Wrangler is only the deploy tool, not part of the app.

Visitors pick up a new build the next time they open the app: the service worker installs it alongside the old one and offers to restart.

## How it fits together

- **Engine.** `engine/swift/Sources/TablesWasm` links `Engine/TablesEngine` and `Engine/TablesMacros` into a WebAssembly reactor that exports a few C functions. Requests and responses are JSON, with file contents passed as raw bytes alongside. `WebSession.swift` ports the Apple apps' editing session (selection, editing, formatting, structure, clipboard, sheets) and adds undo. `Renderer.swift` makes the same decisions as the Mac's cell renderer and returns drawing operations.
- **Worker.** `engine/worker.js` runs the engine off the main thread through a small WASI host (`engine/wasi.js`). The engine has no file system and no network.
- **Grid.** `app/grid.js` draws engine-rendered tiles on a canvas over a native scrolling layer, and adds headers, frozen panes, selection, the cell editor, resizing and the fill handle. `app/paint.js` lays out text, the one thing the browser has to measure.
- **Files.** Files open and save through the File System Access API where the browser has it, and through a file picker and downloads elsewhere. Open documents are autosaved to the browser's private storage, so closing the window loses nothing; Open Recent lists them.
